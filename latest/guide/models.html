Models#

Every neural dynamics model in newton-neural is a torch.nn.Module subclassing NeRDBase and composed of modular, swappable parts. FlashNeRD is the first model family included in the library.

The NeRDBase interface#

All library tools (recording, training losses, stepping, rollout evaluation, and Newton solvers) interact with models strictly through NeRDBase. Any custom model family subclassing NeRDBase works automatically with all of them (see Extending).

Every model exposes two execution paths for the same underlying function:

  • Windowed training (forward()): Evaluates an entire batch of consecutive frame windows in parallel and returns normalized predictions for the loss (Training).

  • Streaming inference (predict()): Evaluates one frame per world at a time via NeRDStepper or a solver, updating fixed-shape per-world history buffers in place (Solvers).

Both paths must produce identical outputs so the deployed model matches the trained one. Use check_nerd_streaming() to verify equivalence for any model family.

Checkpoints and precision#

Each model stores a default deployment precision in NeRDBase.precision ("tf32" for a new model). Steppers and solvers inherit this precision unless overridden; see Performance for the four precision modes.

Saving a model (NeRDBase.save()) writes a single .pt checkpoint containing weights, normalization statistics, frame_dt, precision, signal specifications, model class name, part classes and configs, family settings, and user metadata:

  • NeRDBase.load() instantiates whichever registered model family wrote the checkpoint (used by solvers).

  • Calling <Family>.load (e.g., FlashNeRD.load) enforces that the checkpoint belongs to that family and raises otherwise.

Composable parts#

Every model is built from three core parts. Each part can be swapped independently while keeping the rest of the pipeline (recording signals, labels, losses, and state integration) unchanged:

Part

Built-in classes

Responsibility

System

SystemArticulation

Defines state and control signals, maps raw frames to network features, and integrates predicted increments back into states.

Prediction

PredictionStateIncrement, PredictionFreeMotion

Defines what the network outputs, where supervision labels come from, and which solver consumes the output (Coupling).

Contact input

None, ContactInputProbes, ContactInputSet

Senses contact externally from Newton state or collision buffers and encodes it into a vector for the network (Contact Input).

Systems#

SystemArticulation represents one articulated robot per world with either a fixed or floating base and revolute, prismatic, and fixed joints. Build it directly from a Newton model via from_model().

Bodies and actuated joints (revolute and prismatic) are matched by the final segment of their Newton labels, so every body and every actuated joint within the robot must have a unique label (fixed joints may share labels).

The control parameter selects which newton.Control arrays actuate the robot:

Actuation mode

control argument

Position targets (using Newton’s joint drive gains)

("joint_target_q",) (default)

Position and velocity targets

("joint_target_q", "joint_target_qd")

("joint_f",)

General actuator inputs

("joint_act",)

Everything between the chosen control arrays and the resulting motion, including actuator and PD dynamics simulated by the reference solver, is learned by the network.

For floating-base robots, SystemArticulation expresses features and increments in the base’s heading frame (origin at the base, yaw aligned with the base about the up axis). This makes predictions invariant to horizontal translation and heading angle across worlds.

With PredictionStateIncrement, the network predicts the full one-frame state change (contact effects included) and SolverNeRD integrates it directly. With PredictionFreeMotion, the network predicts unconstrained joint accelerations and SolverNeRDMuJoCo hands them to MuJoCo Warp to resolve contacts with objects. See Contact Input and Coupling.

FlashNeRD#

FlashNeRD is a learned forward-dynamics model family built around explicit external contact input:

  1. External contact sensing. Contact introduces sharp discontinuities that Newton already computes accurately and cheaply. Rather than forcing the network to infer contact geometry from joint states, a contact input senses contact externally via kinematics (ContactInputProbes) or Newton’s collision detector (ContactInputSet), encodes it into a contact code, and injects that code into the network at configurable injection points (contact_injections; see Contact injection points in FlashNeRD).

  2. Streaming temporal forward dynamics. Each frame’s normalized state/control features are embedded, processed by a streaming temporal backbone over a short history window, and mapped to a one-frame prediction by a readout head. At deployment, only the newest frame is computed while past context lives in fixed-size history buffers.

  3. Standalone or coupled deployment. Defaults to PredictionStateIncrement for standalone stepping with SolverNeRD, or swaps to PredictionFreeMotion for two-way coupling via SolverNeRDMuJoCo.

Every argument except system is optional (defaulting to BackboneFlash, no contact input, and PredictionStateIncrement):

nerd = FlashNeRD(
    system,
    backbone=None,
    contact_input=None,
    contact_injections=None,
    prediction=None,
)

Backbones#

The backbone is the temporal trunk mapping embedded frames to hidden states. Backbones are independent of system features, predictions, and contacts, so custom model families can reuse them too.

Backbone

Default receptive field

Notes

BackboneFlash

13 frames

Default. Runs attention and SwiGLU FFN in parallel from a single packed projection with one shared KV head (2 linear layers per block instead of 4).

BackboneTransformer

29 frames

Standard serial multi-head attention + SwiGLU FFN with separate KV per head. Higher step latency than BackboneFlash.

BackboneMLP

4 frames

Lowest step cost; concatenates a fixed window of frames. Use window=1 for single-frame predictions such as PredictionFreeMotion.

The model’s receptive_field is the number of frames (including the current frame) that influence one prediction. For stacked attention blocks where block \(\ell\) attends over \(S_\ell\) frames, spans compound additively:

\[R = 1 + \sum_{\ell} (S_\ell - 1)\]

With BackboneFlash’s default spans=(4, 4, 4, 4), \(R = 1 + 4 \times 3 = 13\). During deployment, each block maintains a fixed-size per-world ring buffer of past keys and values updated in place, so streaming inference matches windowed training exactly at constant per-step cost.
