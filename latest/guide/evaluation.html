Evaluation#

A low one-step training loss does not guarantee accurate closed-loop simulation: during deployment, a model feeds its own predictions back as inputs, allowing small errors to compound. newton_neural.evaluation provides three complementary checks:

Function

What it tests

Input required

rollout_error()

Open-loop drift over multi-step horizons under recorded controls.

TrajectoryWindows

audit_rest()

Creep (drift) and jitter (vibration) when controls are held constant.

One SimulationBase

audit_paired()

Live divergence between candidate and reference solvers from identical states under shared commands.

Two SimulationBase instances

Open-loop rollout error#

rollout_error() rolls a model forward autoregressively using recorded controls and compares the predicted states against the recording at each requested horizon. Use this metric for checkpoint selection on held-out worlds and on policy-generated validation recordings.

Continuing from Training with the trained model nerd and held_out windows:

from newton_neural.evaluation import rollout_error

errors = rollout_error(nerd, held_out, horizons=(1, 16, 64))
for horizon, statistics in errors.items():
    print(horizon, statistics.p50["joint_q"], statistics.p99["joint_q"], statistics.nrmse)
after_reset = rollout_error(nerd, held_out, horizons=(1, 16, 64), from_episode_start=True)

Each horizon maps to a RolloutStatistics object:

  • mean, p50, p90, p99: Per-signal absolute state errors (via system.error, in each signal’s SI unit; floating-base orientation is reported as a single rotation angle in radians), aggregated across rollouts and coordinates. Because rollout errors are heavy-tailed, inspect p50/p90/p99 alongside mean.

  • nrmse: Prefix-averaged normalized RMSE over frames \(1 \dots H\), channels, and rollouts: system.increment(recorded, predicted) / nerd.output_normalizer.std. A value of 1.0 corresponds to an RMS error equal to one typical single-frame state change in the training set.

Key options and caveats:

  • Window length: windows can have any length; rollout_error() re-slices rollouts of length history + max(horizons) from the same worlds.

  • Primed history vs. fresh reset: By default, rollouts start anywhere in an episode after priming the history with receptive_field - 1 recorded frames. Passing from_episode_start=True evaluates rollouts starting at frame 0 with an empty history, matching solver behavior immediately after a reset. RL environments reset frequently, so measure both.

  • Subsampling: rollout_count defaults to 4096 evenly spaced start points (since adjacent-frame starts overlap heavily). Pass rollout_count=None to evaluate every possible rollout.

  • Contact inputs: Recomputable inputs (ContactInputProbes) are re-evaluated at every predicted state. Non-recomputable inputs (ContactInputSet) reuse the recorded contact rows from the ground-truth trajectory, so long-horizon rollout errors are less representative once the predicted trajectory diverges; pair them with audit_paired().

  • Deployment parity: Pass precision and compile to match deployment settings (defaults: checkpoint precision, compiled on CUDA). Compare against precision="fp32" before shipping reduced precision (Performance).

Rest stability audit#

Models with low rollout error can still slowly creep or oscillate at rest, which RL policies quickly exploit. audit_rest() holds the current controls fixed for frame_count steps and reports two metrics per state signal:

  • Drift (drift_mean, drift_max): Absolute state difference between frame 0 and frame frame_count.

  • Vibration (vibration_mean, vibration_max): RMS residual of each coordinate over time after subtracting the least-squares linear trend, separating high-frequency jitter from steady creep. The trend is fitted to the system’s increments from frame 0, so a floating base is detrended as a rotation, as long as it turns less than half a turn during the audit.

Bring both the reference and candidate simulations to a steady pose (e.g., holding standing targets) and compare them side by side. Below, model, system, and reach come from Recording:

import newton

from newton_neural.data import CommandHeld, SimulationNewton
from newton_neural.evaluation import audit_paired, audit_rest
from newton_neural.solvers import SolverNeRD

mujoco = newton.solvers.SolverMuJoCo(model)
reference = SimulationNewton(model, mujoco, system, frame_dt=0.02, substep_count=4)
candidate = SimulationNewton(model, SolverNeRD(model, nerd), system, frame_dt=0.02)

for simulation in (reference, candidate):
    rest = audit_rest(simulation, frame_count=100)
    print(rest.drift_max["joint_q"], rest.vibration_max["joint_q"])

Paired live audit#

audit_paired() restarts both simulations from the reference’s current state, steps both live under the same command stream for frame_count frames, and returns per-frame mean and max state differences (shape [frame_count] per signal). The state is that of the robot, so other bodies of a scene, such as a free object, start where a restart puts them in both simulations:

commands = CommandHeld((10, 50), low=-reach, high=reach)
paired = audit_paired(reference, candidate, commands=commands, frame_count=100)
print(paired.mean["joint_q"][-1].item(), paired.max["joint_q"][-1].item())

Because audit_paired() runs live simulations (including live collision detection for ContactInputSet), it requires no pre-recorded dataset and can probe arbitrary states reached by stepping the reference under an RL policy.
