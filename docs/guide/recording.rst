.. currentmodule:: newton_neural.data

Recording
=========

Training data is generated by running a reference physics solver in parallel across many worlds, resetting each world
to sampled starting states, applying sampled control commands, and writing every frame's signals to a sharded
dataset on disk.

All code blocks on this page run end to end on Newton's cartpole with small sizes so they execute in seconds on CPU.

.. testcode::

    import newton
    import newton.examples
    import torch

    from newton_neural.data import CommandHeld, SamplerUniform, SimulationNewton, TrajectoryRecorder
    from newton_neural.models import FlashNeRD
    from newton_neural.systems import SystemArticulation

    robot = newton.ModelBuilder()
    robot.default_joint_cfg.target_ke = 100.0  # Position-controlled joints
    robot.default_joint_cfg.target_kd = 10.0
    asset = newton.examples.get_asset("cartpole.urdf")
    robot.add_urdf(asset, floating=False, enable_self_collisions=False)
    scene = newton.ModelBuilder()
    scene.replicate(robot, 64)
    model = scene.finalize()

1. Define the system
--------------------

Extract a :class:`~newton_neural.systems.SystemArticulation` from the Newton model. This specification defines the
robot's state and control signals and is embedded in every saved checkpoint.

.. testcode::

    system = SystemArticulation.from_model(model)
    print(list(system.signals))

.. testoutput::

    ['joint_q', 'joint_qd', 'joint_target_q']

By default, ``control`` is ``("joint_target_q",)``. Pass ``control=("joint_f",)`` for torque/force control, or pass
the robot's articulation label pattern as the second argument when a world contains multiple articulations.

2. Wrap the reference solver
----------------------------

:class:`SimulationNewton` pairs a Newton model with a solver to step full frames, apply commands, and reset subsets
of worlds.

.. testcode::

    mujoco = newton.solvers.SolverMuJoCo(model)
    simulation = SimulationNewton(model, mujoco, system, frame_dt=0.02, substep_count=4)

Each frame advances ``frame_dt=0.02`` s using 4 solver substeps of ``0.005`` s. The trained model will step once per
``0.02`` s frame.

.. note::

    The reference solver must keep ``state.joint_q`` and ``state.joint_qd`` synchronized. This holds for
    generalized-coordinate solvers such as :class:`newton.solvers.SolverMuJoCo` and
    :class:`newton.solvers.SolverFeatherstone`, but not for maximal-coordinate solvers like
    :class:`newton.solvers.SolverXPBD`. Pass ``collision_pipeline`` if the solver or a contact input requires
    Newton-detected contacts (see :doc:`contact`).

    Newton leaves external actuators (``model.actuators``, added with ``ModelBuilder.add_actuator`` or authored
    as USD actuator prims) to the caller of the solver to step. :class:`SimulationNewton` does not step them and
    refuses a model that holds any, since their forces would be missing from every frame. Step such a model in a
    :class:`SimulationBase` subclass of your own (see :doc:`extending`).

3. Instantiate the model to declare signals
-------------------------------------------

Pass an untrained model instance to :class:`TrajectoryRecorder`. The recorder queries the model via
:meth:`~newton_neural.models.NeRDBase.sources` to determine every signal to capture: pre-step state and contact
signals, plus post-step controls and prediction labels.

.. testcode::

    nerd = FlashNeRD(system).to(simulation.device)

This works with any :class:`~newton_neural.models.NeRDBase` configuration (:doc:`models`). To record arbitrary custom
signals without a model, pass a list of :class:`SignalSource` objects instead (:doc:`extending`).

4. Configure state samplers and commands
----------------------------------------

Each world runs independent episodes: it resets to a sampled state, follows a command generator for a random episode
length drawn from ``episode_frames`` (default ``(200, 400)``), and resets again.

.. testcode::

    reach = torch.tensor([1.0, 1.5, 1.5], device=simulation.device)  # cart [m], two poles [rad]
    recorder = TrajectoryRecorder(
        simulation,
        nerd,
        states=SamplerUniform({"joint_q": (-reach, reach), "joint_qd": (-reach, reach)}),
        commands=CommandHeld((10, 50), low=-reach, high=reach),
        episode_frames=(100, 200),
    )

If you omit ``states`` or ``commands``, the recorder defaults to :class:`SamplerSobol` over
:meth:`SimulationBase.state_bounds` and :class:`CommandHeld` (holding random commands for 1–25 frames) over
:meth:`SimulationBase.command_bounds`. Those bounds come from Newton's joint limits (see
:meth:`~newton_neural.systems.BindingArticulation.state_bounds`), which are often wider than your operating region.
Narrow them explicitly as above so simulation budget is spent on relevant states.

.. list-table::
   :widths: 28 72
   :header-rows: 1

   * - State sampler
     - Behavior
   * - :class:`SamplerSobol`
     - Low-discrepancy Sobol sequence over the state box *(default)*.
   * - :class:`SamplerUniform`
     - Independent uniform samples per channel within bounds.
   * - :class:`SamplerFloatingBase`
     - Perturbs a nominal floating-base pose by base position offsets, tilt angle, and linear/angular/joint speeds.
   * - :class:`SamplerPerturb`
     - Adds Gaussian noise to states drawn from another sampler.
   * - :class:`SamplerMixture`
     - Weighted random selection among multiple samplers.

.. list-table::
   :widths: 28 72
   :header-rows: 1

   * - Command generator
     - Behavior
   * - :class:`CommandHeld`
     - Piecewise-constant random commands held for a random frame range *(default)*.
   * - :class:`CommandSmooth`
     - Temporally correlated smooth noise within bounds.
   * - :class:`CommandSweep`
     - Frequency-sweeping sinusoids (chirp excitation).
   * - :class:`CommandNearState`
     - Resamples position targets near current ``joint_q`` every frame.
   * - :class:`CommandSwitch`
     - Selects one of several command generators per episode.

To build a custom sampler or command generator:

- Subclass :class:`SamplerBase` and implement ``sample(count)`` returning ``count`` starting states.
- Subclass :class:`CommandBase` and implement ``next(frames)`` returning one command vector per world. Before frame
  0, the recorder initializes the command with ``world_count``, ``low``, ``high``, ``frame_dt``, and ``generator``.

**Divergence and settling.** Any world whose state becomes non-finite or exceeds ``1000`` in SI units resets
immediately, and the offending frame is marked ``valid=False``. Setting ``settle_frame_count > 0`` simulates initial
frames after each reset (marked invalid) so penetrations from random initial poses resolve before valid data starts.

5. Record the dataset
---------------------

.. testcode::

    dataset = recorder.record("data/cartpole", frame_count=128)
    nerd.save(dataset.path / "flashnerd.pt")
    print(dataset.world_count, dataset.frame_count, dataset.frame_dt)
    print(dataset.arrays(0)["joint_q"].shape)

.. testoutput::

    64 128 0.02
    (64, 128, 3)

``record()`` simulates ``frame_count`` frames per world and writes a :class:`TrajectoryDataset` directory containing
``meta.json`` and one or more shards (default ``shard_frame_count=256``). Each shard stores memory-mapped ``.npy``
arrays of shape ``[world_count, shard_frames, *shape]`` for every signal, plus boolean ``episode_start`` and
``valid`` masks. Calling :meth:`TrajectoryRecorder.record` a second time continues from the current simulation state
into a new output directory.

.. tip::

    Save the untrained model checkpoint directly inside the dataset folder (as above). Datasets store only signals
    and generation metadata, not model architecture, so saving the untrained checkpoint beside the data lets your
    training script load the exact model definition with ``FlashNeRD.load()`` without duplicating configuration code.
    Extra files inside a dataset directory are ignored by :class:`TrajectoryDataset`.

If recording is interrupted or raises mid-run, all completed shards remain readable on disk with
``dataset.generation["complete"] == False``, while the exception still propagates.

To write datasets from custom simulation loops outside :class:`TrajectoryRecorder`, use :class:`TrajectoryWriter`
(which copies each shard synchronously before returning and flushes to disk on a background thread).

Independent single-step samples
-------------------------------

Passing ``episode_frames=(1, 1)`` resets every world on every frame, producing independent single-step samples. Use
this for :class:`~newton_neural.predictions.PredictionFreeMotion`, whose label is recorded on the same frame
(:doc:`coupling`). Models using :class:`~newton_neural.predictions.PredictionStateIncrement` supervise against the
next frame and therefore require at least ``episode_frames=(2, 2)``.

Data coverage guidelines
------------------------

Model accuracy is bounded by what the dataset covers. Pay attention to three factors:

- **States:** Cover the full workspace and velocity envelope the robot will encounter, with safety margin.
- **Commands:** Match how controls vary at deployment (step changes, smooth trajectories, tracking near current pose).
- **Contact balance:** When using a contact input, verify that both in-contact and free-space frames are well
  represented (for example, by inspecting the ``touching`` channel ``contact_probes[..., 7]`` or ``contact_count``).
